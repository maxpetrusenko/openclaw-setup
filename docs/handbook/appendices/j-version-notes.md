# Appendix J: Version Notes

## Why It Matters
It tells us what to trust from the handbook and what to verify against current docs.

## Core Ideas
- Mental models and patterns age slower than exact flags and config keys.
- Tool parameters, model names, and current integrations are the most likely to drift.

## Patterns To Keep
- Treat the handbook as durable on concepts, provisional on specifics.
- Verify runtime details before coding or operating.

## What To Adopt In OpenClaw
- Add “verify against current docs” checkpoints before implementation work based on handbook notes.

## Risks / Limits
- False confidence from stale examples.

## Open Questions
- Which handbook assumptions already conflict with the current repo or product?
