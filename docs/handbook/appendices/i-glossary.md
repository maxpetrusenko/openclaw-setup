# Appendix I: Glossary

## Why It Matters
Shared language reduces routing and debugging mistakes.

## Core Ideas
- Terms like agent, artifact, gate, handoff, heartbeat, and idempotent are operational, not academic.
- A stable vocabulary makes docs and prompts shorter and clearer.

## Patterns To Keep
- Reuse glossary terms consistently across docs.
- Prefer handbook vocabulary for control-plane concepts.

## What To Adopt In OpenClaw
- Standardize key terms in protocol docs and planning docs.
- Add repo-specific terms only when truly needed.

## Risks / Limits
- Glossaries help only if the language is enforced in practice.

## Open Questions
- Which terms are overloaded in this repo today?
- Do we need a repo-local glossary extension?
